# Telegram-бот «60 FPS»

Принимает видео и перекодирует его в 60 FPS с интерполяцией кадров (FFmpeg,
`minterpolate`), после чего отправляет результат обратно пользователю.

## Как устроено

- Два процесса: асинхронный бот (`bot.py`) и воркер FFmpeg (`ffmpeg_worker.py`),
  обмен — через очереди `multiprocessing`. Тяжёлое кодирование не блокирует бот.
- Одна активная задача на пользователя; общая очередь до `QUEUE_MAXSIZE` задач.
- Лимиты: вход до `MAX_FILE_SIZE_BYTES` (50 МБ), результат до
  `MAX_UPLOAD_BYTES` (45 МБ, ограничение Telegram Bot API).
- Если готовый файл не влезает в лимит отправки, воркер автоматически пережимает
  его сильнее (`FALLBACK_CRF`) — повторная интерполяция не требуется.
- Вотчдог каждые `WORKER_CHECK_INTERVAL` секунд проверяет воркер: если тот упал,
  все зависшие задачи получают ошибку (пользователь не «зависает» навсегда),
  а воркер перезапускается.
- Ожидание результата ограничено `JOB_TIMEOUT_SECONDS`, временные каталоги
  задач удаляются после обработки, устаревшие — при старте.

## Требования

- Python 3.10+
- FFmpeg в `PATH`
- Токен бота от [@BotFather](https://t.me/BotFather)

## Локальный запуск

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows (source .venv/bin/activate — Linux/macOS)
pip install -r requirements.txt

# создай .env: BOT_TOKEN=123456:ABC-DEF...
python bot.py
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота (обязателен) |
| `ALLOWED_USER_IDS` | пусто (все) | Вайтлист: ID пользователей через запятую |
| `QUEUE_MAXSIZE` | `10` | Размер очереди задач |
| `MAX_FILE_SIZE_BYTES` | `52428800` | Максимальный размер входного видео (50 МБ) |
| `MAX_UPLOAD_BYTES` | `47185920` | Максимальный размер результата (45 МБ) |
| `FFMPEG_TIMEOUT` | `300` | Таймаут одного запуска FFmpeg, сек |
| `FFMPEG_PRESET` | `fast` | Пресет libx264 для основного прохода |
| `FFMPEG_CRF` | `20` | CRF основного прохода (меньше — качество выше) |
| `FALLBACK_CRF` | `28` | CRF автопережатия при превышении лимита |
| `JOB_TIMEOUT_SECONDS` | `QUEUE_MAXSIZE * FFMPEG_TIMEOUT + 300` | Максимум ожидания результата задачи |
| `WORKER_CHECK_INTERVAL` | `5` | Период проверки живости воркера, сек |
| `JOB_ROOT` | `<tempdir>/tg60fps_jobs` | Каталог временных файлов задач |
| `LOG_DIR` | `logs` | Каталог логов (ротация 5 МБ × 3) |
| `STALE_JOB_TTL_SECONDS` | `86400` | Возраст устаревших каталогов задач |

## Docker

```bash
docker build -t tg60fps .
docker run --rm -e BOT_TOKEN="123456:ABC-DEF..." tg60fps
```

## Замечания по производительности

`minterpolate` сильно нагружает CPU: обработка может занять в разы больше
времени, чем длится само видео. Для длинных роликов увеличивайте
`FFMPEG_TIMEOUT` или присылайте видео покороче. Качество/скорость/размер
регулируются `FFMPEG_PRESET` и `FFMPEG_CRF`.
